# Set up Shared Memory

**Experimental prerelease `v0.2.0-alpha.1`.** Runtime version: `0.2.0`.
Obsidian is optional. Use a disposable project or a backed-up working copy for your
first trial. Stable V1, independent-recipient and real-provider acceptance are not
claimed. Release assets must actually be available before downloading them.

Copy the entire block into an agent running on or connected to your computer.
There are no placeholders to edit.

```text
Set up experimental Shared Memory for my selected project folder, or join the
existing project whose owner supplied my instructions. Start from:
https://github.com/Kian-hdr/shared-memory/releases/tag/v0.2.0-alpha.1

Discover my OS, compatible Python 3.11+, exact project folder and create/join intent.
Use a disposable project or backed-up working copy for this alpha trial. A selected
subfolder in my existing private vault is a valid project. Preserve its parent,
siblings, home, instructions, settings and unrelated artifacts. Ordinary setup needs
no Obsidian installation, vault registration or app launch.

Obtain shared-memory-0.2.0-alpha.1.pyz and SHA256SUMS from that release when present.
Compare the downloaded file's SHA-256 with the external checksum before executing
it. Verify version, capabilities and the supplied guide, and read my project's
existing instructions. If the asset is absent or mismatched, stop package execution
and identify the missing reviewed source; do not silently use latest main, an
unpublished candidate or the older advisory tracker. Optional skill installation
uses the complete matching skill archive, verifies its external checksum before
extraction and preserves any existing installation.

Reuse working components and complete routine authorized local setup. Keep tools,
tokens, connection settings, drafts, backups and SQLite in my own private local,
non-synchronized storage outside the project. Install only missing compatible
Python or optional server dependencies needed for the chosen workflow. Respect
required sign-in, MFA, OS consent and agent permissions. Ask only for essential
inputs that cannot be discovered. Do not send messages, invite members, change
sharing/accounts, purchase or deploy a server without that action's authorization.

For a new owner project, use init with my distinct person/agent/actor identity.
Enable schema 2 explicitly when setting up session coordination, using the guide's
configuration and my own session credential. Local-only requires no server or
cloud account. Preserve existing schema-1 state unless an explicitly authorized
upgrade has a reviewed full-history plan and verified private backup.

For joining, use attach with my independently issued private member token, expected
project ID and authorized reachable coordinator endpoint, plus my own local folder
and state directory. Never copy the owner's identity, local paths or credentials,
initialize a second authority, or silently upgrade while joining. Team serving
requires an operator-owned reachable host and verified TLS; this package does not
provide a hosted service. Provider access and coordinator membership are separate.

Refresh accepted context, inspect team-status and verify receipt. Explain bounded
work acquisition, drafts with base revision and evidence, submission for integration
owner acceptance, conflict preservation and receipt-checked handoff. Schema-2 drafts
must retain their acquired session/generation/policy/input context. Preserve journals,
drafts and history through documented recovery; do not delete them to make checks pass.

If provider delivery is selected, follow the exact package's documented route and
prove downloaded revision/hash before a normal refresh can supply coordinator bytes.
A local fixture or provider-check is not proof of real provider delivery. Do not
silently substitute coordinator content for a failed provider download. Use graph
diagnostics when links matter; product alias resolution is not native Obsidian proof.

Report the exact package/checksum, project identity, actor, local receipt and any
coordinator/provider/device checks separately. Complete feasible local work and mark
external gates unavailable or unverified. After owner setup, return a project-specific
teammate prompt in chat with actual approved package/access locators, no credentials
or sender-local paths, and unknown access clearly marked. Do not send it automatically.
Do not migrate or restructure my live vault or alter backup drives during onboarding.
```
