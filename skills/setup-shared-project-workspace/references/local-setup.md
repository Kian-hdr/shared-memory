# Local environment readiness

Discover the selected existing folder and installed compatible Python 3.11+. A local
agent can complete normal installation and repair steps within the user's request;
keep actual OS/admin/sign-in controls explicit. Do not invent a Homebrew or app
requirement when working Python and a normal directory already exist.

Verify the runtime's external SHA-256 before execution. Use immutable private tools
storage and the exact returned installed package path. Record enough local discovery
for another agent to resume without copying another person's private state.

Obsidian is optional. Ordinary setup does not install it, open/register a vault or
change `.obsidian`. If the user explicitly asks for app setup, use the installed
app's actual state and scope. Preserve existing settings and recovery copies.

Confirm the chosen folder's files are actually downloaded for offline work. Resolve
unsafe path or placeholder errors through the provider's supported local-file route;
do not hide them with symlinks or weaken runtime checks. Keep baselines/recovery in
local non-synchronized private storage outside the shared folder. The shared history
is a deliberate part of folder-mode synchronization, not a private SQLite database.

See [storage and access](storage-access.md) for provider boundaries and
[product runtime routing](product-runtime.md) for setup versus migration.
