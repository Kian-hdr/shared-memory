# Share one project folder

The selected project is the access boundary. Each person can keep that shared folder
inside a larger private vault when the chosen provider supports the local placement.
A plain Markdown folder works equally well. Do not move the project, create a new
vault, introduce a symlink or share its parent just to fit a remembered layout.

Read governing instructions locally, but never copy confidential parent context into
the share implicitly. Preserve homes, existing instructions, attachments, settings
and nested legacy tracker history. If the work depends on inaccessible context,
state the missing input rather than widening access.

Normal folder mode stores portable change history with the shared project. Each
computer has a separate private baseline; do not distribute another person's private
recovery state, credentials or session history. All editors use the same compatible
project format and one provider. Format-1/2 coordinator projects need explicit
backed-up migration, not a second setup pretending to be the same project.

Links should resolve within the intended share or point to deliberately authorized
external references. A private sibling link does not grant access and may reveal its
title. Obsidian graph visibility and native rename behavior are separate from provider
permissions and Shared Memory history; check affected links after a move.

See [storage access](storage-access.md) and [teammate onboarding](teammate-onboarding.md).
